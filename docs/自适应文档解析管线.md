# 自适应文档解析管线

本文档描述当前 `src/mindforge/ingestion/parsers.py` 的实际行为。运行参数以项目根目录 `.env` 为准，`.env.example` 提供完整键清单。

## 目标

同一条上传与索引链路处理四类 PDF：

1. 可复制的原生文本 PDF。
2. 纯扫描或图片型 PDF。
3. 原生文本和扫描页混合的 PDF。
4. 包含表格和嵌入图片的 PDF。

管线不以“整份 PDF 是否可复制”为判断依据，而是按页决定是否需要 OCR，避免普通文本 PDF 因 OCR 产生不必要的延迟。

## 处理流程

```text
上传字节进度
  -> 原生文本检测（pdfplumber）
  -> 每页质量判断
  -> 低质量页 OCR（PaddleOCR）
  -> 按需表格识别
  -> 结构化 DocumentElement
  -> 元素感知分块
  -> Embedding / Qdrant / BM25
```

- 原生文本页直接使用 `pdfplumber`，大文件仍使用既有的多进程或多线程页提取。
- 空页、短文本页或文本质量不足的页在 `PARSER_MODE=auto` 时进入 OCR。
- OCR 使用 PaddleOCR 3 的 `predict()` 接口，按文本行保留坐标和置信度。
- 原生候选表格通过 `pdfplumber` 提取并转换为 Markdown。扫描页的表格仅在 OCR 文本布局显示出多列特征时才启动 Paddle 的表格识别模型。
- 嵌入图片记录为 `image` 元素，包含页码、边界框和基础图像属性。当前检索仍是文本向量检索，图片不会伪装成文本 Chunk；该元素模型是后续接入视觉 Embedding 的接口。

## 结构化元素

每个元素包含以下字段：

| 字段 | 说明 |
|---|---|
| `kind` | `text`、`table` 或 `image` |
| `content` | 可索引的文本或 Markdown 表格；图片目前为空 |
| `page` | 从 1 开始的 PDF 页码 |
| `bbox` | `[x0, y0, x1, y1]` 坐标，存在时保留 |
| `confidence` | OCR 识别置信度，原生文本为空 |
| `source_method` | `native_text`、`ocr`、`native_table`、`ocr_table` 或 `embedded_pdf_image` |
| `metadata` | 表格行列数、OCR 行序号或图像属性等附加信息 |

元素感知分块会将 `page`、`element_type`、`bbox`、`ocr_confidence` 和 `source_method` 写进向量与 BM25 的元数据。表格在不超过 Chunk 上限时保持完整，避免破坏行列关系。

## 配置

| 环境变量 | 默认值 | 作用 |
|---|---:|---|
| `PARSER_MODE` | `auto` | `auto`、`native`、`ocr` |
| `PARSER_OCR_ENABLED` | `true` | 是否允许低质量页进入 OCR |
| `PARSER_OCR_DEVICE` | `cpu` | PaddleOCR 推理设备 |
| `PARSER_OCR_MODEL_SOURCE` | `BOS` | Paddle 模型下载源；服务器网络使用 BOS |
| `PARSER_OCR_ENABLE_MKLDNN` | `false` | CPU oneDNN 兼容开关；当前模型组合默认关闭 |
| `PARSER_OCR_DPI` | `200` | OCR 页渲染分辨率 |
| `PARSER_OCR_MIN_NATIVE_TEXT_CHARS` | `30` | 低于该字符数时判定为 OCR 候选页 |
| `PARSER_OCR_MAX_PAGES` | `600` | 单份文档最多 OCR 页数 |
| `PARSER_TABLE_EXTRACTION_ENABLED` | `true` | 启用表格提取 |
| `PARSER_TABLE_MAX_CELLS` | `10000` | 单张表最大单元格数 |
| `PARSER_IMAGE_EXTRACTION_ENABLED` | `true` | 记录 PDF 嵌入图片元素 |
| `PARSER_IMAGE_MAX_PER_PAGE` | `20` | 每页最多记录图片数 |

GPU 服务器默认不强制让 PaddleOCR 使用 GPU。当前容器的 CUDA/Torch 组合服务于 Embedding 和 Reranker，Paddle GPU 轮子需要单独验证后再将 `PARSER_OCR_DEVICE` 改为 GPU；在此之前 CPU OCR 保持可预测的运行行为。

部署时，`PADDLE_PDX_CACHE_HOME` 指向 Docker 已挂载的模型缓存卷，`PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=true` 跳过每次进程启动时的外部连通性检查。两项设置与 `PARSER_OCR_MODEL_SOURCE=BOS` 一起避免容器重建后重复下载模型。

## 进度与失败语义

异步索引任务会依次报告 `detecting`、`ocr`、`layout`、`table`、`chunking`、`embedding`、`vector_store` 和 `bm25` 等阶段。前端上传弹窗显示这些阶段和服务端进度。

OCR 失败不会丢弃同页已经提取到的原生文本。仅当整份文档在原生提取和 OCR 后都没有可索引文本时，任务才以 422 失败并明确提示。图片元素本身尚未进入视觉向量索引，因此纯图片且没有可识别文字的文档仍不能进入当前文本知识库。
